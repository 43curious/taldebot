# Public homepage mobile layout

Issue #19 changes the shared `StudentLanding.astro` used by `/` and `/en/`. The homepage preserves its original airline-code appearance: separate rounded white code fields with soft shadows, a teal-accented letter field and a floating teal start button. There is no surrounding card; the code label and format hint remain available to screen readers.

The fixed-width code row is now a six-column grid with five flexible fields and a narrow separator. Field height, font size and gaps scale with available width, using defined CSS dimensions. Each field has an accessible label; digits request a numeric keyboard and the letter requests text/uppercase. The start button reserves its space while hidden, then fades and slides into view when the complete code is valid. Clearing a field hides and disables it again. Reduced-motion settings suppress the animation. The compact header keeps language and admin access reachable; on narrow screens admin access uses a labeled icon. The header, content and footer participate in normal flow so short screens can scroll rather than clipping controls.

`studentLanding.ts` retains uppercase normalization, whole-code paste (including separators), partial digit paste, forward focus, backspace correction, arrow navigation, invalid-code feedback, localized routing and language switching. Layout/validation requires no database calls. Both homepage routes remain prerendered in the production build.

## Verification

A Chromium browser checked both languages at 320, 390, 430 and 1280px. Code fields remained within the viewport, at least 44px tall and 40px wide, with no horizontal page overflow; the footer did not overlap the form. A 390×360 short viewport remained scrollable with usable controls. Functional checks covered invalid input, complete-code paste, lowercase-letter normalization, backspace correction, project routing, invalid-code feedback and switching language.

Before screenshots of the current public deployment were captured anonymously at 320px and 390px on 17 October 2026. The 320px baseline clips the outer code fields and admin-access link. Local after screenshots at 320px and 390px in both languages show the whole control/header within the viewport. These are viewport-emulation checks, not physical-device Safari/Android or software-keyboard tests. Those real-device checks remain pending. The production build confirms `/index.html` and `/en/index.html`; this layout change adds no schema migration.

On 18 October 2026, the original code-field styling and animated start button were restored following feedback on the initial mobile redesign. Chromium checks of the production build passed for both languages at 320, 390, 430 and 1280px, plus a short 390×360 viewport. These checked field bounds and touch sizes, complete-code paste, button reveal/hide after correction, localized submission and reduced motion. Screenshots captured the restored appearance at 320 and 1280px. The production build and Astro type check passed, with one existing hint in the classes page.
